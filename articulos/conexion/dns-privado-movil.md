# Diez claves para utilizar DNS privado en el móvil

Puedes proteger las consultas de nombres de tu móvil sin confundirlas con toda tu conexión. Aprende qué cambiar, qué comprobar y cómo volver atrás.

El móvil necesita traducir nombres de páginas en direcciones de red. El DNS privado protege ese paso en determinadas condiciones. Antes de tocarlo, conviene saber qué protege y a quién entregas las consultas.

## Protege una consulta concreta

El sistema de nombres de dominio, o DNS, ayuda a encontrar la dirección de un servicio a partir de su nombre. Cifrar esa consulta limita quién puede leerla durante el trayecto hasta el proveedor elegido. No cifra por ello todos los datos que envías después a la página. Piensa en una pregunta protegida dentro de una conversación más amplia: el resto de las conexiones conserva sus propias protecciones y sus propios límites.

## El proveedor sigue teniendo una función

Elegir un servicio de DNS también supone elegir quién responde a tus consultas. Revisa quién lo mantiene, qué explica sobre registros y cómo resuelve incidencias. Una política de privacidad clara permite valorar ese intercambio, pero el nombre «privado» del ajuste no certifica que el proveedor carezca de datos. No copies la dirección de una publicación anónima solo porque prometa bloquearlo todo o acelerar cualquier conexión sin explicar sus condiciones.

## Busca el ajuste de tu sistema

En Android, la ayuda de Google sitúa DNS privado en Redes e Internet y permite buscar ese nombre si el fabricante cambia la ruta. Hay opciones de desactivado, automático y nombre de host del proveedor. Comprueba primero qué tienes seleccionado y conserva una nota. Este ajuste pertenece a Android: no traslades la misma ruta al iPhone ni instales un perfil desconocido para conseguir que aparezca una pantalla parecida.

## Automático y proveedor fijo son distintos

La opción automática y la elección de un proveedor concreto no expresan la misma preferencia. Google recomienda mantener DNS privado activado y documenta esas opciones por separado. Si quieres usar un proveedor determinado, consulta sus instrucciones para Android y escribe el nombre de host que publique. No sustituyas ese nombre por una dirección numérica encontrada en otra guía: los campos de configuración no son intercambiables y pueden requerir datos de formato diferente.

## Copia el nombre desde su documentación

Los proveedores pueden ofrecer varios servicios, con filtrado de amenazas o con otras políticas. Cloudflare y Quad9 documentan direcciones y modalidades distintas. Comprueba cuál has elegido antes de guardarla y no atribuyas al servicio básico las funciones de otra modalidad. Si buscas bloquear dominios conocidos como maliciosos, lee también cómo consultar un bloqueo equivocado. Una lista de filtrado puede ayudar, pero no decide si una compra o un mensaje son fiables.

## Prueba ambas formas de conexión

Después de guardar el cambio, abre servicios conocidos mediante wifi y mediante datos móviles, si dispones de ambas conexiones. Anota si falla una red concreta o todo el dispositivo. Esta prueba comprueba que puedes conectarte en esas condiciones; no demuestra por sí sola que cada aplicación utilice el mismo DNS. Si el proveedor ofrece una página oficial de diagnóstico, úsala entendiendo qué verifica y evita instalar certificados para completar una comprobación rutinaria.

## Considera las opciones del navegador

Un navegador o una aplicación puede gestionar sus conexiones de forma distinta del ajuste general. También una VPN puede cambiar qué consultas se hacen y por dónde pasan. Antes de concluir que hay una filtración, revisa la documentación de los componentes que utilizas y modifica una sola opción cada vez. Añadir varias herramientas de privacidad sin conocer su relación complica el diagnóstico y puede hacer que atribuyas al DNS un fallo provocado por otra capa.

## El filtrado tiene límites prácticos

Bloquear un dominio puede impedir conexiones a ese nombre, pero no identifica todo el contenido servido desde él. Un mismo dominio puede alojar funciones útiles y elementos que no quieres cargar. Tampoco todos los rastreadores usan un nombre separado que resulte fácil bloquear. Si una aplicación deja de funcionar, investiga la causa antes de permitir todas las consultas o de dar por hecho que el bloqueo prueba una actividad maliciosa.

## Conserva una salida si algo falla

Si pierdes acceso justo después del cambio, vuelve al ajuste anterior que anotaste y prueba de nuevo. Comprueba también si esa red requiere completar una página de acceso. No aceptes un certificado inesperado ni desactives las alertas del navegador para recuperar la conexión. Si solo falla el proveedor elegido, consulta su ayuda desde otra conexión disponible. Recuperar el servicio con el estado anterior no obliga a abandonar para siempre el DNS cifrado.

## Elige según tu objetivo real

Antes de seguir cambiando opciones, decide si quieres cifrar consultas, aplicar un filtrado concreto o investigar un fallo. Cada objetivo requiere una comprobación diferente y ninguno convierte el móvil en anónimo. Utiliza la tabla para elegir un primer paso y guarda el resultado junto al ajuste anterior. Si no puedes explicar qué mejora esperas obtener, mantener una configuración documentada puede ser una decisión más útil que acumular servicios elegidos al azar.

## Por dónde empezar

Mira qué opción utiliza ahora tu móvil y anótala. Si decides cambiarla, prueba primero servicios conocidos y conserva una forma de volver atrás.
